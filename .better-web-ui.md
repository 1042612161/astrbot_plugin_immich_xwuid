## Design Context

### Users
AstrBot administrators maintaining an Immich library of character images and mapping those albums to the existing XWUID panel-image and background-image galleries. Their jobs are to find the correct role and album quickly, review mappings, select roles, run syncs, and understand progress or failures without losing page context.

### Brand Personality
Clear, calm, and lightly playful. The audience is operating a technical admin tool; anime influence should appear as restrained warmth and color, not decorative noise. The interface should feel trustworthy and make operational state easy to scan.

### Aesthetic Direction
Use a dark, low-glare palette with deep graphite and blue-black surfaces, clear cool-gray text, and restrained lavender and teal accents. Prefer a fresh, operations-focused layout rather than carrying forward earlier page compositions. Keep the interface calm and legible, with contrast reserved for active controls and task state. The mapping workspace and batch-selection area must have deliberate boundaries, stable widths, and responsive stacking so their controls never overlap. Preserve editable text fields for both album specification names, panel/background tabs, searchable role-to-album mappings, batch role selection, and task status above the work area. Avoid native multi-select controls, unfiltered cross-type album choices, and status messages hidden below the page. Keep responsive behavior usable in AstrBot's embedded plugin view.

### Implementation Defaults
The existing project uses a plain AstrBot plugin page with HTML, vanilla CSS, and browser JavaScript in `views/gallery-sync/`, communicating with the AstrBot view bridge. Preserve this detected stack and the host page conventions; do not add a frontend framework or component dependency. Use native text inputs for editable specification names. Build the preview as a local, self-contained HTML page with mock data and simulated actions; never connect it to production services.

### Design Principles
1. Establish task hierarchy with alignment, spacing, and clear section boundaries before adding decorative effects.
2. Keep mapping and batch selection in separate, predictable regions; stack them cleanly on narrow screens.
3. Search narrows the visible set without discarding selections or changing saved mappings.
4. A type-specific album picker only offers albums whose suffix matches that type's editable specification.
5. Put progress, completion, and recoverable failure details above the work area so users do not need to hunt for results.
